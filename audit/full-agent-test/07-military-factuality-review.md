# 军事事实可靠性终稿

结论：verified 模式现在由服务端证据控制，不能由客户端伪造；无证据或证据冲突时不会生成确定性军事事实画面。

## 已修复的事实链

- `ClaimValidator` 对国家/国别、型号、原型/量产、服役/当前状态等中英文谓词做别名归一和冲突判定。
- 不存在型号、无来源、低质量来源、缺失原文 quote、低于置信阈值的 claim 标为 unsupported；可靠来源给出互斥精确值时标为 conflicted。
- `SourceType.OTHER` 的生产评分上限为 0.59，固定 relevance/timeliness 加分不能再让单一随机博客跨过 0.65 的低置信验证阈值。
- “当前/在役”类 claim 要求发布日期在允许窗口内；陈旧来源和未来日期都不能证明当前状态。
- visual fact 同样执行最低置信度、source/quote 约束；分镜只能引用当前 snapshot 中存在且可用的 claim/visual fact ID。
- `research/gate.py` 使用服务端 project/job/snapshot，核对完成状态、research 标记、revision/hash、来源、provenance 和 scene 映射。
- 无语义重叠的“通用 claim”不再自动附着到任意旁白。verified prompt 丢弃模型自由文本，只保留已验证 claim 的 subject；环境、动作、镜头和收尾由服务端标为通用非识别创作并经 `prompt_renderer` 确定性生成。
- 恶意模型提示中的“六台发动机、十二枚核导弹、红色国籍标志、具名前线基地”不会进入 snapshot 的 `media_prompt`，不一致 visual-fact ID 也会在生成前移除。
- 来源不足时降级为普通生成并带 warnings；verified 模式则 fail closed，不把模型猜测包装成事实。
- 网页中的提示注入在证据抽取前被拒绝，来源发生重定向后重新执行公共 URL 校验。

## 直接覆盖的军事场景

正常历史/博物馆主题、名称含糊、虚构型号、同名不同国家、原型与量产冲突、历史与当前冲突、多可靠来源冲突、仅低质来源、完全无来源、陈旧/未来来源均有确定性测试。完整映射见 `09-test-coverage.md`。

## 安全内容边界

系统允许历史、新闻、博物馆、法律与高层次技术教育；拒绝可执行攻击规划、现实目标选择、武器/爆炸物制造、规避侦测/执法和现实伤害操作指南。门禁同时作用于用户输入和模型输出。

取舍：当前 verified 画面采用保守的 `verified_generic` 表达，不自动渲染型号特有挂载、标志或基地；这会降低画面具体度，但避免把模型猜测包装成证据事实。事实校验仍不等同于专业情报鉴定，真实世界状态可能变化，高影响发布仍需领域人员复核。
